# 0.3.23：同步桌面与统计程序的服务器地址

桌面客户端 `0.3.23` 内含统计程序 `0.2.5`。中央后端和管理网页仍使用已发布的 [server-v0.3.23](https://github.com/3240665200/Codex-Quota-Guard/releases/tag/server-v0.3.23)，本次客户端修复不要求更新服务器镜像。

## 安装

下载本 Release 的 `Codex.Quota.Guard_0.3.23_x64-setup.exe`。先从系统托盘退出旧客户端，再安装、启动新版，并登录目标服务器完成统计程序配对。安装包包含 Java 17 与 WebView2 离线组件，随附 `SHA256SUMS.txt` 可校验下载文件。

## 地址切换

在登录页面或启动检查页面修改服务器地址并保存时，先同步 Windows 统计服务；同步成功后才保存桌面设置。取消管理员授权或配置失败时不会提示保存成功。操作期间禁止重复保存和登录。完成后按页面提示从系统托盘退出客户端、重新启动，再登录目标服务器。

跨服务器切换会创建独立统计状态，保留原服务器的队列、凭据及扫描进度。旧扫描边界到切换时之间归属不明的用量和未完成日志行单独保留，不计入新账户。旧队列为空也不会通过直接重写服务器字段来迁移。已经出现 `METER_OUTBOX_IDENTITY_MISMATCH` 的旧安装会在统计服务配置修复时检查同样的迁移条件。

配对文件新增服务器来源校验，避免仍在运行的旧客户端将旧服务器的配对凭据交给新服务。新服务需由新版客户端登录后重新配对。统计日志保持原有目录，页面仍可读取。

## 数据位置

新统计状态位于 Windows 公共应用数据目录的 `CodexQuotaGuard\Meter\contexts\<标识>`，由 SYSTEM 和管理员访问。原统计目录保留。新目录中的 `server-state-prepared.json` 记录准备边界；`archived-outbox.json`、`archived-scan-state.json` 和 `unknown-usage.json` 用于核对旧记录，不会自动提交到新服务器。

- Java 配对服务：14 项通过。
- 打包流程的客户端 Java 回归：177 项通过、2 项跳过；内嵌资源与真实 WebView 启动检查通过。
- Windows PowerShell 5.1：地址切换判断、旧状态修复、原子配置替换失败保留原文件，以及启动策略和安装预检通过。

上述测试使用合成数据，没有修改本机实际用量记录。安装包产物与校验文件保存在项目 `dist/desktop-v0.3.23`。
