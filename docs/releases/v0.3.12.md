# v0.3.12 — 结束 CC Switch 后恢复 Codex 连接

本版本修复 Quota Guard 结束 CC Switch 后，Codex 配置仍指向已停止的本地路由、后续请求可能报错的问题。

## 连接恢复

- 确认 CC Switch 已结束后，自动恢复能够明确识别为 CC Switch 接管的 Codex 连接配置；客户端隐藏到托盘时同样生效，首次启动也会检查此前遗留的接管配置。
- 优先使用 CC Switch 保存的原连接备份；没有备份时，仅使用明确选中的原供应商配置，不猜测服务地址或凭据。
- 保留现有 OAuth 登录、模型、MCP、权限及其他用户设置；保留旧会话引用的供应商标识，不回滚 OAuth token。
- Windows 提示区分配置已恢复、无需修改和恢复失败；失败时显示具体原因，可在修正问题后点击“重新检查”。

自动恢复支持当前 Windows 用户的标准 `.codex`、`.cc-switch` 目录。自定义目录、恢复来源不可靠、配置被并发修改或无法写入时会明确提示失败，不继续启动本地业务服务。恢复成功表示配置已保存，并不代表已验证网络连通；已有 Codex 进程或聊天仍报错时，请重启 Codex 或重新打开会话以重载配置。

## 更新方式

从系统托盘退出旧版 Quota Guard，再覆盖安装新版。完成安装后以当前 Windows 用户的管理员身份运行。仅关闭窗口会保留托盘运行，不能代替退出。

本次恢复功能在桌面端实现，随包 Rust 统计程序保持 **0.2.2**；已安装统计程序 0.2.2 的电脑无需为此单独升级统计程序。服务器版继续使用 **0.3.11**，本次无需更新中央服务、管理网页或执行数据库迁移。

## 下载附件

- `Codex-Quota-Guard_0.3.12_x64-setup.exe`：Windows x64 桌面安装包，包含本地 Java 17、WebView2 离线安装程序及 Rust 统计程序 0.2.2，用户电脑无需开发环境。
- `SHA256SUMS.txt`：安装包的 SHA-256 校验值。

安装包未进行代码签名，Windows 可能提示未知发布者。中央服务与管理网页不包含在桌面安装程序内。
