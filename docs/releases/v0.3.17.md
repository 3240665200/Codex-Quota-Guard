# 0.3.17 本地测试版

## 本次变化

- 自动绑定：申请登录名额后，在官方 Codex 应用中完成登录即可。中央后台每隔至少 10 秒检查官方会话；没有新增会话则继续等待，唯一新增 Codex 会话经下一次新鲜快照复核后自动保存绑定。客户端不再要求点击“已完成登录”或“确认绑定”。多个候选、候选变化或身份异常会安全结束任务并整理队列；完成、取消、超时或失败会释放当前任务拥有的邮件监听。
- 窗口恢复：同一用户仍有效的已授权页面保持挂载。窗口取得焦点或恢复可见时重新核验，期间禁用导航和内容交互，避免反复卸载产生闪跳；返回时立即校验时钟，许可过期、被拒绝或核验失败仍会关闭访问。自动绑定完成后重新核对中央权限。
- 按用户登出的配套改动：本轮同时准备管理网页和中央后台的系统用户范围会话登出功能。该能力不包含在桌面安装包中；其中央部署与实际验证结果由后续说明补充，本说明不代表真实官方登出已成功。

## 配套与边界

- 自动绑定必须配套更新中央后台；单独替换桌面安装包不能使旧中央后台自动识别和保存。管理网页也需配套更新，正确区分自动复核推断和历史用户确认推断。
- 桌面版本统一为 0.3.17，Rust 统计程序仍为 0.2.3；安装范围、自启动及已有用户配置保持原策略。保留 0.3.14、0.3.15、0.3.16 旧测试包。
- 既有排队最长 60 分钟，取得登录名额后有 30 分钟完成登录。后台短暂不可用或限流时保留同一任务与候选，按 10、20、40、60 秒退避，最长 60 秒；不会延长原到期时间。身份、设备、团队或连接版本变化仍会终止任务。
- 内部代次、操作令牌与租约防止旧工作覆盖新任务。两个一致的快照仍只是归属推断，不能证明物理设备身份，也不能完全排除第三方不受控的迟到登录；取消后请停止旧官方登录页面。
- 保留旧手动 API 仅作兼容，新客户端流程不调用检测或确认 API。状态由中央返回并通过既有实时通知更新，客户端不自行合成绑定成功。

## 手工验收

1. 在测试机从托盘退出旧客户端，再覆盖安装 0.3.17；沿用原中央地址与配置。
2. 配套中央后台准备完成后申请绑定，取得名额再在官方 Codex 登录。观察后台自动识别、复核并显示已绑定，界面不出现“已完成登录”或“确认绑定”按钮。
3. 在尚未出现新增会话时持续等待，确认任务仍有效；取消或到期后确认邮件监听释放、队列自动整理并交接。
4. 从其他窗口切回客户端，确认仍有效的已授权页面保持显示，核验期间导航和内容不可交互；许可过期、被拒绝或检查失败后关闭访问。需要用户进一步检查真实 Windows 拖动与切窗视觉效果，本轮未执行该视觉复验。
5. 真实官方登录、邮件认证及管理员按用户登出，由用户在配套服务就绪后验收。模拟测试与隔离验包不代表这些真实操作已经成功。
