## 新增功能

- **持久订阅管理**：支持 URI 列表、Base64 和 Clash/Mihomo YAML 顶层 `proxies`；首次导入下载，后续由管理员手动更新，没有定时更新任务。订阅 URL 加密保存，摘要不回显 URL、用户名或密码。旧无状态 `/proxy-nodes/import` 继续返回 410。
- **稳定的节点引用**：同订阅按唯一节点名称保留节点 ID；来源消失的节点标为缺失并停用，重现后仍需管理员启用。主动停用的节点不会因刷新重新启用。下载、解析或版本检查失败保留原节点，删除订阅只解除来源关系并保留节点及账户引用。
- **每账户前置／出口链**：出口必选，前置可选，两个位置不能选择同一节点。官方读取、刷新、会话操作及绑定所需刷新使用该账户保存的链；任一所选节点缺失、停用或故障即停止请求，不省略前置，也不回退直连。
- **只更新账户代理链**：已有授权可单独保存链，无需重填 Authorization 或 Cookie。保留现有加密授权和已验证身份，使旧会话快照失效；保存后需重新刷新官方账户与会话。
- **完整链路测试**：返回当次组合的最终出口 IP、地区与测试结果，不覆盖单节点测试记录，不发送官方授权或 Cookie。
- **Trojan URI 兼容**：支持 `peer` 作为 `sni` 别名；两者同时存在时须一致，冲突明确报错。URI 中编码的用户名与受限订阅下载也纳入兼容处理。

订阅仅接受公网 HTTPS 443、无 URL 用户信息和重定向，最多 1 MiB、128 个唯一名称节点。支持已实现的 HTTP、HTTPS、SOCKS5、Shadowsocks、VMess、VLESS、Trojan 协议变体；不执行完整 Clash 配置中的规则、DNS、TUN、监听器、脚本或嵌套 provider，不支持的参数会使整次更新失败。下载使用固定 `User-Agent: Codex-Quota-Guard`，与官方账户链分开，不携带官方凭据。Fake-IP 补查仍验证公网地址、固定连接 IP 并保持原域名 TLS 校验。完整范围见[订阅与代理链说明](../proxy-subscriptions-and-chains.md)。

## Trojan 证书例外范围

新建订阅的 `allowInsecureTrojan` 默认 false。仅当管理员在该订阅中明确许可，且该订阅的 Trojan URI 自身声明 `allowInsecure=1` 或 `true` 时，才允许对应节点跳过节点证书校验；`0` 或 `false` 继续校验。此例外接受节点提供的任意证书，不能验证该节点身份。

许可不扩散到其它订阅、其它协议、Clash YAML、订阅下载 HTTPS 或官方站点 HTTPS。未许可时返回 `PROXY_TROJAN_TLS_CONFIRMATION_REQUIRED`，别名冲突返回 `PROXY_TROJAN_SNI_CONFLICT`，错误不包含原始链接或凭据。关闭许可或解除订阅来源会立即恢复相关节点的证书校验、停用节点并清除旧出口测试，保留节点 ID 和账户引用；之后手动启用不会恢复旧例外。修改 URL 或开启许可后仍需手动更新节点获取新配置。

## 数据库与升级

从服务器 `0.3.22` 升级会执行：

| 迁移 | 变更 |
| --- | --- |
| V32 | 账户连接增加可空 `front_proxy_node_id`，保留原必选出口 |
| V33 | 增加加密订阅表、节点来源和唯一名称关系 |
| V34 | 订阅增加默认 false 的 `allow_insecure_trojan`；旧订阅不自动获得许可 |

从 `0.3.18/0.3.19/0.3.20` 升级还会执行 V31；从 `0.3.11` 升级执行 V22–V34，并须遵守 V29 的全部旧写入进程停写要求。迁移不清库，不重写已有授权或代理凭据。

1. 使用原配置停止全部旧应用，保持 PostgreSQL 运行。备份数据库与原 `.env`，另存项目名、卷名、Compose/overlay、证书、私有预置和全部加密密钥。
2. 同时更新后端与管理网页到 `0.3.23`，保留原数据库卷、项目名、HTTP/HTTPS 配置及密钥；不要重新 `init`、更换密钥或删除数据库卷。桌面继续使用 `0.3.22`。
3. 确认 Flyway 到 V34、容器健康和管理员登录，验证既有单出口账户及客户端访问；按需导入订阅、手动更新节点、测试完整链路并保存账户链，再刷新官方账户与会话。

旧应用不理解前置链，可能直接连接出口，不能把直接换回旧镜像视作相同网络策略。降级到不理解 Trojan 许可的代码前，应先在新版关闭该例外并确认节点恢复校验。V32 历史脚本的应用回滚注释不能取代这些运行限制；不要改写已执行 SQL、执行 Flyway repair 或删列。确需恢复升级前状态时，停止官方请求并恢复相互匹配的数据库、应用、配置和密钥备份，详见[部署升级步骤](../../deploy/docker/registry/README.md#升级到-0323)。
