# 桌面 0.3.26：独立统计服务状态修复

> 桌面登录的旧 HTML 安全策略问题已在 [0.3.27](https://github.com/3240665200/Codex-Quota-Guard/releases/tag/v0.3.27) 修复，请使用新版桌面。统计服务 0.2.7 的独立计量修复保持有效。

Windows 统计服务升级到 **0.2.7**，兼容当前中央后台 **0.3.25**。

此前，超过后台 30 天接收范围或时间超前的待传记录会使统计程序的整体状态显示为“异常”，即使服务已经成功上报了新用量。修复后，服务把这类记录单独标记为待核对警告，保留原始事件 ID、时间、归属与用量，新记录及心跳持续上传。权限、网络、授权、队列损坏及归属不一致仍保留真实故障提示，不将警告转换为成功入账。

桌面“统计程序”页面单独展示待核对警告和记录数量。当前有效用量仍按原接收窗口、事件 ID 去重与账户归属规则上传，不修改历史时间以绕过校验，不清空旧队列。

计量、离线持久队列、设备凭据续期和心跳都由独立 Windows 服务负责。桌面完全退出后，服务继续运行；系统故障恢复保持 5/5/30 秒重启策略和非崩溃失败恢复。实际使用仍需要 Windows 已启动、服务未被管理员禁用，并能读取 Codex 会话日志；断网期间保留事件，恢复网络后补传。

验证包含统计程序 93 项测试、桌面前端 257 项测试、原生状态读取 6 项测试、真实生产二进制的独立进程/离线重启补传验证，以及本机实际 SCM 服务在桌面进程为零时的上传、心跳与服务器入库核验。协议测试使用隔离临时数据；实机验证只观察真实产生的用量，不插入虚构计费事件。

独立进程测试可复现：

```powershell
node apps/client/meter/tests/independent-process.mjs <已编译的统计程序.exe> <测试报告目录>
```

安装包继续携带 WebView2 离线安装器，不包含 Java 或本地 HTTP 后端。更换 Windows 服务程序需要管理员授权；升级保留已有设备配对、用量归属、扫描游标和待传记录。
