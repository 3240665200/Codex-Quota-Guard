# 0.3.18 本地测试版

## 本次修复

- 恢复同一条已保存的 BOUND 绑定记录时，不再重复把已经通过的访问核验硬重置。只有需要重新确认的绑定变化才触发对应处理，其他菜单仍以中央返回的访问许可为准。
- Dashboard 维持并共享登录辅助 SSE 订阅，减少切页和 React StrictMode 生命周期引发的重复连接与重建；该订阅仍只通知状态变化，最新状态按当前登录身份重新读取。
- 区分“绑定记录已保存”和“当前访问权限已核验通过”。核验失败时保持访问关闭，并显示经过安全处理的错误类别，方便复测，避免绑定卡显示成功却让用户误以为权限检查也已通过。

## 范围与限制

- 本轮仅更新桌面客户端，不需要重新更新或重启中央后台。Java 后端仅新增诊断测试，生产逻辑未修改；Rust 统计程序保持 `0.2.3`，安装与自启动策略不变。
- 已修复可复现的重复 BOUND 通知重置与 SSE 生命周期问题。首次访问请求失败的底层原因尚未取得证据，不能声称网络或服务异常已全部修复。新版本的安全错误分类用于后续复测定位。
- 暂时失败后恢复为允许访问的桥接行为已通过合成测试；这不能代替真实环境网络或服务可用性的验证，也不会把访问失败改成自动放行。
- 保留 0.3.14、0.3.15、0.3.16、0.3.17 旧测试安装包。本轮不执行安装器，不正常启动真实客户端或统计守卫，不调用真实官方会话或邮件，不发布 GitHub 或 Docker。

## 手工验收

1. 从托盘退出旧客户端，再覆盖安装 0.3.18，沿用已有中央地址和配置。
2. 打开已有绑定记录，观察不会因同一条 BOUND 结果反复重置已核验权限；切换页面后状态仍一致。
3. 切换登录辅助与其他页面，观察状态更新和访问核验是否稳定。取得焦点或恢复可见时仍应重新核验，期间禁用交互；拒绝、过期或检查失败仍关闭访问。
4. 若再次出现“绑定状态核验失败”，记录新版提示中的安全错误类别与发生时间；已保存的绑定记录不等于当前访问检查成功。该问题的首次底层失败原因仍待真实复测证据。
