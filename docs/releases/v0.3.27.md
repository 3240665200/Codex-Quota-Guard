# 桌面 0.3.27：修复中央服务器请求被页面安全策略拦截

0.3.25/0.3.26 桌面端改用 Axios 直连中央 API 后，HTML 页面中仍保留旧版只允许本机 IPC 的 `connect-src`，与 Tauri 允许 HTTP/HTTPS 的策略叠加生效。因此服务器和跨域响应正常时，WebView 仍会在本机拦截登录请求，界面显示“无法连接中央服务器”。

本次同步修正 HTML 的连接策略，允许用户配置的 HTTP/HTTPS 服务，保留脚本来源、表单、页面基址等原有安全限制。请求继续由 JS Axios 发送，没有新增 Java、本地业务后端或客户端保活程序。

发布检查新增真实 WebView 的 `fetch` 和 XHR 跨域请求，携带与客户端相同名称的设备请求头。默认打包检查只使用隔离的临时本机测试端点，不依赖公网，也不读取真实账号、口令或登录状态；页面能渲染但网络受策略拦截时，构建不得通过。额外验证实际中央服务器的未登录请求能返回预期 401，不将连通性探测描述为真实账户登录成功。

本次只更新桌面端。继续使用统计服务 **0.2.7** 和中央后台 **0.3.25**，保留已有配对、用量记录及服务器配置。Windows x64 安装包保留 Microsoft 签名的 WebView2 离线安装器。
