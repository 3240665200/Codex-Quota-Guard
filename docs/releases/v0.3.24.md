# 0.3.24 源码变更：团队成员用量与独立统计架构（未发布）

桌面端配额页面分为“团队 Token”和“官方 Token”。团队区域包含共享额度、当前用户个人额度，以及当前团队所有成员的用量明细。每位成员同时显示两组进度条：5 小时/7 天个人剩余额度，以及其 5 小时/7 天/累计用量占团队已用总量的比例。条形图旁保留具体 Token 数字。成员列表支持按姓名搜索，标记当前用户、停用状态，并保留零用量成员。

个人剩余以各自个人限额和个人重置时间为准；未设个人限额会明确标注，零限额或耗尽时显示 0% 剩余。团队占比的分母为对应时段的团队已用总量，并非团队限额。两种百分比分开呈现，避免将团队贡献误算为个人额度消耗。

官方区域继续展示官方返回的额度百分比和重置时间，不将百分比换算成虚构的 Token 数量。深浅色主题沿用现有设计；窄窗口下成员表格独立横向滚动。

## 配套后台

成员明细需要部署本次中央后台代码。新版桌面通过 `GET /api/v1/client/quota/overview?includeTeamMembers=true` 主动请求 `teamMembers`；原路径不加参数时保留旧响应结构，兼容旧桌面和用量上报接口。

后台只根据已登录用户的当前团队返回成员，不接受指定其他团队。数据仅含成员 ID、显示名称、状态、5 小时/7 天/累计团队贡献用量、个人限额及剩余量和最近有效上报时间，不返回邮箱、设备信息、会话或凭据。采用批量查询：团队用量遵守团队重置时间及事件上报时保存的团队归属；个人剩余遵守个人重置时间，计入本人跨团队的个人消耗，不披露其他团队明细。成员请求使用一致读快照。已离队成员的历史用量仍可计入团队合计，因此当前成员的占比合计可能不足 100%。

连接尚未更新的后台时，新桌面会显示“服务器尚未提供成员用量，请更新服务器”，不会将缺失数据显示成零。本次源码不包含数据库迁移；配套统计程序源码升级至 `0.2.6`。

## 独立统计架构

桌面业务请求改为 JS Axios 直接访问中央 API，移除本地 Java HTTP 后端及其运行时打包。Tauri 仅提供必要系统操作：DPAPI 会话存储、设备身份与配对文件、本机 Codex CLI RPC、窗口/托盘、只读服务状态和脱敏诊断。

Rust 服务成为唯一计量程序，兼容旧累计日志，并使本地持久采集独立于慢网络上报。安装包强制安装并启动服务，配置 Windows 自动启动、5/5/30 秒故障重启和非崩溃失败恢复；客户端不再自动安装、修复、保活或兜底采集。用户更改服务器地址时，通过专用脚本更新已有服务，失败回滚，旧队列与归属保留。

旧 Java 加密会话文件保留，升级后可能需要重新登录一次。WebView2 仍使用离线安装器。
