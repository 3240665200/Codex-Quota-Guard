# v0.3.10 — 登录辅助、双发件地址与七天登录态

本次公开发布包含自 v0.3.8 以来的桌面登录辅助、七天登录态，以及最新中央服务和管理后台修复。

## 登录辅助与邮箱兼容

- 桌面「登录辅助」可监听管理员自有邮箱中的新到登录邮件；收到一份符合规则的验证码后自动停止。客户端只取得验证码与任务状态，不取得邮箱授权或邮件正文。
- 管理后台增加「发件地址 1 / 2」，两个完整地址同时生效，保留单地址兼容；不使用域名通配匹配。
- 支持中英文登录码及条件式安全提醒，修复短模板、HTML 预览与正文同码重复、就绪状态发布前新邮件被过滤等问题。
- 改善网易 IMAP ID、缺失 UIDNEXT 的兼容，以及代理 Fake-IP DNS 场景的有界备用解析；始终校验 TLS 证书。
- 同一邮箱一次只允许一个活动监听。若后台测试提示邮箱正在被监听，请先在桌面取消监听，或等待收码/超时后重试。

## 七天登录态

- Windows 桌面端登录系统账户后，在本机加密保留登录状态，最长 7 天；正常退出应用、重启客户端或电脑后自动验证并恢复。
- 期限从成功登录时固定计算，后台自动刷新不会无限续期；主动退出登录清除状态，管理员强制下线或禁用仍然生效。
- 不保存密码，不把系统令牌交给网页界面；密钥由当前 Windows 用户的 DPAPI 保护，会话按中央服务器地址隔离。
- 恢复登录仍需通过现有管理员、统计程序及设备配对检查。统计服务继续独立运行，官方 Codex 登录方式不变。

## 更新方式

从托盘退出旧版客户端，再覆盖安装新版。首次升级需登录一次，之后开始保留 7 天状态。已安装 0.3.10 的用户无需为本次邮件识别修复重装客户端，更新中央服务与管理网页即可。

邮箱登录辅助需要配套的中央 Java 后端、PostgreSQL 和管理网页。由 0.3.8 升级时，先备份数据库和服务配置，再更新中央服务；Flyway V21 新增邮箱配置/监听表，不修改已有用户和额度数据。已应用 V21 的服务不需要额外迁移。需要独立、持久保存的 `MAIL_ASSISTANCE_ENCRYPTION_KEY`；不要重新生成已在使用的密钥。详见[邮箱配置与使用说明](https://github.com/3240665200/Codex-Quota-Guard/blob/v0.3.10/docs/architecture/login-assistance.md)和[中央服务部署说明](https://github.com/3240665200/Codex-Quota-Guard/blob/v0.3.10/apps/admin/backend/README.md)。

## 下载附件

- `Codex-Quota-Guard_0.3.10_x64-setup.exe`：Windows x64 桌面安装包，包含本地 Java 17、WebView2 离线安装程序及 Rust 统计程序。用户电脑无需开发环境。安装包未签名，Windows 可能提示未知发布者。
- `Codex-Quota-Guard-Server_0.3.10.jar`：中央服务，需要服务器提供 Java 17、PostgreSQL 及原有数据库/JWT/邮箱加密配置；它不是桌面内的本地 Java 服务。
- `Codex-Quota-Guard-Admin-Web_0.3.10.zip`：管理网页静态文件，需由 Web 服务器托管，并将 `/api` 反向代理至中央服务。
- `SHA256SUMS.txt`：上述文件的 SHA-256 校验值。

中央服务与管理网页不包含在桌面安装程序内。发布附件不包含用户配置、数据库、真实邮件、授权码或登录令牌。

短暂离线可以稍后重试恢复。若中央凭据已撤销、会话到期，或一次性刷新成功后响应丢失，则需重新登录。密钥、文件权限或多实例冲突会显示明确的本机存储错误，不会悄悄降级为明文保存。

## 验证

客户端沿用本版已验证且未发生源码变化的构建：本地 Java 共 124 项测试，122 项通过、2 项真实服务或平台权限测试跳过；行覆盖率 82.14%。桌面前端 147 项、Rust 150 项测试通过，4 项既有实际环境检查保持跳过，类型检查与严格 Rust 检查通过。

最新中央后端共 325 项测试，322 项通过、3 项需显式授权的诊断测试默认跳过。邮箱配置页面 18 项测试、管理前端类型检查与生产构建通过。另已针对所有者提供的真实中英文邮件文件离线验证解码与识别，仅输出脱敏结果；这不替代每个部署环境的实际新邮件收取验收。

仓库当前未配置 GitHub Actions 工作流；上述验证为本地执行结果，并非云端 CI 结果。本次未在全新电脑上重新执行安装测试。

另外使用随包 Java、模拟中央接口和临时目录运行了真实进程重启测试：验证缺少存储密钥时报错但诊断可用、重复实例被锁阻止、关闭进程后恢复并轮换凭据，以及退出登录后再次启动不恢复。未使用真实用户凭据，未启动桌面冲突守卫。

开发者可在准备好随包 JAR 与 Java 运行时后，在 `apps/client/frontend` 执行 `pnpm test:session-persistence` 复跑隔离测试。
