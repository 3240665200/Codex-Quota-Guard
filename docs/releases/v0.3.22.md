# 0.3.22：桌面连接修复、CC Switch 共存与必选账户代理

版本日期：2026-10-16。公开版本包括 Windows x64 桌面客户端 `0.3.22`、独立统计程序 `0.2.4`，以及 Linux amd64 中央后端与管理网页 `0.3.22`。源码标签为 `v0.3.22`。

## 本次变更

- 桌面端修复 HTTP／HTTPS 服务器地址访问，保留统一服务器设置、设备配对与绑定校验，移除旧官方登录助手。官方 Codex 登录仍由用户在官方应用或 CLI 完成。
- CC Switch 默认允许共存。只有当前账户明确使用 API Key、处于 `PROXY_MANAGED` 且没有 OAuth，并且活动 CC Switch 数据库记录证明正在接管 Codex，才判定冲突。原生统计服务还会核验受保护 `ProgramData` 证据、同一 SID／SessionId 和精确进程身份，再结束冲突进程并提示。普通网络错误、仅安装或运行 CC Switch 均不会触发结束进程；冲突进程中未保存的内容可能丢失。
- 每个官方账户必须绑定已启用代理节点，访问模式为 `REQUIRED`。未选、禁用、不可用或连接故障时拒绝官方请求，不回退直连。
- 代理管理改为填写名称、HTTP／HTTPS／SOCKS5、主机、端口及可选用户名／密码。订阅、分享链接和 URI 导入已停用，`/admin/proxy-nodes/import` 返回 410。既有节点和加密凭据保留。
- 代理测试经所选节点访问固定 HTTPS 出口检测地址，显示出口 IP、国家、地区、城市、测试时间与状态，不发送官方 Authorization／Cookie，不接受自定义目标。测试成功不等于官方接口可用。
- V31 仅增加代理出口测试元数据：可空出口／位置／时间字段和带默认值的测试状态，不改写节点配置或凭据。

## 升级

1. 停止旧应用写入，保留 PostgreSQL 运行，备份数据库、原 `.env`、Compose／overlay、证书及私有预置；备份应加密保存。保留原项目名、数据库卷、JWT 和全部加密密钥，禁止重新初始化或执行 `docker compose down -v`。
2. 后端与管理网页同时更新至 `0.3.22`，建议升级桌面至 `0.3.22`，确认统计程序为 `0.2.4`。普通后端不再叠加旧 browser overlay；原有 HTTPS 部署继续携带 HTTPS overlay。
3. 确认 Flyway 完成 V31。**在任何官方账户请求前，先为该账户选择已启用代理**；原先直连的账户不会自动选节点。验收代理出口测试、管理员登录、授权／会话管理、设备绑定和客户端访问。

从 `0.3.20` 升级新增 V31；从 `0.3.11` 升级会执行 V22–V31，V29 前必须停止全部旧 writer，不能新旧实例混跑。跨历史迁移回退不能只切旧镜像；详细步骤见 [Docker Hub 升级说明](../../deploy/docker/registry/README.md#升级到-0322)。
