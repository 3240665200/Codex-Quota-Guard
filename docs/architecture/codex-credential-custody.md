# Codex 授权与凭据保管

## 结论与当前进度

管理网站支持「授权添加」和已有 JSON 凭据导入。授权添加使用 **官方 Codex CLI 的网页登录 / 设备码登录**，由 Java 后端管理授权过程，没有依赖 CLIProxyAPI 服务，也没有自行模拟 OpenAI 密码登录。

管理端已实现授权入库与访问控制，管理员可以把一个托管 Codex 账户分配给系统用户；
桌面端必须先登录本系统账号，且已移除本机 Codex 登录入口。分配、取消分配和强制下线
都会通过会话版本使该系统用户的旧会话失效。团队与个人额度策略由中央 Java 服务计算，
客户端旧“共享房间”模块已移除。**尚未实现服务器受控的 Codex 任务执行、可靠的逐人
用量计量或客户端远程工作区，也没有提供向客户端下发凭据的接口。**

要满足“客户端用户无法从自己的电脑提取上游凭据”，上游凭据就不能到达那台电脑。将凭据写入本地官方 Codex 的 `auth.json`、内存或系统凭据库后，加密文件、混淆程序、隐藏接口都无法保证机器所有者提取不到。

客户端只让用户登录本系统、无须填写 API 地址或密钥。当前已经采用“凭据留在服务器”
的边界；已配置的额度策略可以安全展示，但个人用量与任务执行必须继续通过受控的服务器执行层完成。

## 管理员如何添加

1. 进入「Codex 账户 → 授权添加」，填写用于识别的名称。
2. 浏览器与 Java 后台同机时选择「网页登录 → 前往官方登录」，页面自动打开官方登录地址；浏览器拦截弹窗时使用手动打开按钮。OpenAI 密码只在官方页面输入。
3. 后台在远程服务器时选择「设备码登录」，在官方页面 `https://auth.openai.com/codex/device` 登录并输入管理端显示的一次性验证码。需在 ChatGPT 安全设置中允许设备码登录；工作区账户可能需要工作区管理员允许。
4. 回到管理端，服务器检测成功后自动读取授权账户邮箱，加密入库，并删除临时凭据。重复邮箱不会覆盖原账户。
5. 不再需要时选择「取消授权」。关闭页面后的取消可能因网络中断失败，服务器也会独立处理超时。

验证码仅用于此次授权，不是可下载或可交付给客户端的登录凭据，请勿转发。只有发起授权的管理员能查看该验证码。

网页登录的 OAuth 链接同样仅对发起管理员可见，不记录在日志中。官方 CLI 使用 PKCE 与 state，并在后台机器的 `localhost:1455` 接收回调；网站域名不会自动成为 OpenAI 的回调地址。
因此远程部署不能仅改成一个公网 callback URL，也不应将 1455 端口暴露到公网。后端会阻止并发网页登录，并在启动前检查端口占用；不要在这段期间另启同端口的登录进程。授权成功后读取临时 JSON、AES-256-GCM 加密入库、清理临时文件；管理员无须手动下载或上传 JSON。

### 导入已有文件

在有权管理该账户的管理员电脑上运行：

```sh
codex -c cli_auth_credentials_store=file login
```

常见路径是 Windows 的 `%USERPROFILE%\.codex\auth.json`，或 macOS/Linux 的 `~/.codex/auth.json`。若配置了 `CODEX_HOME`，使用该目录中的文件。系统凭据库模式可能不生成文件。

`auth.json` 等同密码，不能发给客户端用户。JSON 导入只检查对象格式和大小，并不向上游验证有效期；不要把 `hasCredential` 当作上游账户在线证明。

官方参考：[认证与凭据存储](https://learn.chatgpt.com/docs/auth)、[App Server 登录协议](https://learn.chatgpt.com/docs/app-server)。

## 部署条件

- 管理 API 主机安装支持 `chatgpt` / `chatgptDeviceCode` 的官方 Codex CLI。本机协议已对照 `0.155.0-alpha.9.2` 的生成 schema；部署时固定版本并验证，不保证所有旧版本支持。
- `CODEX_LOGIN_COMMAND` 指向实际可执行文件。Windows 建议使用完整 `codex.exe` 路径，不使用依赖交互终端的 shell 别名。
- `CODEX_AUTH_WORK_DIR` 是服务器临时父目录，例如 `D:/BuildCache/pingche/private`。程序只在其下建立专用 `codex-quota-guard-authorizations/login-*` 目录。此父目录不得通过静态文件服务、共享盘或客户端工具暴露。
- 配置独立、稳定、至少 32 字节的 `CODEX_CREDENTIAL_ENCRYPTION_KEY`，不得与 `JWT_SECRET` 相同。未配置时拒绝新增/替换 Codex 凭据和发起授权，不会悄悄换密钥。
- 老版本若曾用 JWT 密钥回退加密，应先备份并规划服务端重加密；直接改密钥会使原密文不可读。本轮不自动迁移或重置旧密钥。
- 密钥使用服务端密钥管理设施注入，单独备份，禁止存放在源码、前端构建产物、数据库同一备份中。生产 HTTPS、管理端访问限制、数据库最小权限仍必需。
- `.env.example` 是配置样例，Spring Boot 本身不会自动加载 `.env` 文件；应由部署系统导入环境变量。

## 已实现的防护

| 边界 | 防护 |
| --- | --- |
| 管理接口 | 后端 `ADMIN` 权限；授权会话归属检查；随机会话 ID；响应 `no-store` |
| 授权生命周期 | 10 分钟超时；同一管理员单个活动授权；15 秒启动间隔；全局最多 4 个活动进程 |
| 强制下线 | 授权前与入库事务内检查管理员状态、角色和会话版本；撤销后不再入库 |
| 官方登录进程 | 独立 `CODEX_HOME` 与工作目录；只通过私有 stdio 调用固定登录方法；不暴露通用 RPC、工具或模型执行 |
| 网页跳转 | 前后端校验官方 HTTPS 域名、PKCE 和本机回调；拒绝重复查询参数；新窗口隔离 opener、禁止 Referer；提供弹窗拦截后的手动入口 |
| 临时文件 | Linux/macOS 目录 `0700`；Windows 仅目录所有者 ACL；完成/取消/超时/正常服务退出时清理；清理失败拒绝入库并报警 |
| 环境变量 | 子进程只继承运行、系统、网络所需环境变量，不继承数据库密码、JWT 或凭据加密密钥 |
| 永久存储 | AES-256-GCM、随机 IV、账户 UUID 绑定认证数据；查询仅返回账户元数据 |
| 错误处理 | 不向 API 返回原始上游错误、日志、令牌或服务器路径；请求对象的文本表示脱敏 |

这里的“凭据不下发”针对普通客户端用户，不等于能抵御已攻陷的服务器、服务器管理员或泄露的密钥。Java/CLI 运行时仍需短暂持有明文；JVM 字符串无法保证物理内存擦除。

进程强杀、断电等异常退出可能留下仅服务器所有者可读的临时目录。本版本没有跨实例孤儿进程回收器；生产部署应在确认没有活动登录进程后清理残留 `login-*` 目录，临时目录排除备份并使用受保护的磁盘。删除文件也不等于 SSD 上可验证的安全擦除。

## 客户端与后续执行层：不能越过的边界

当前数据流（会话、账户分配和策略投影已实现；受控执行与逐人计量尚未实现）：

```text
客户端（本系统可撤销会话）
  → Java 会话、账户分配、权限与配额控制
    → 受控凭据使用层（上游令牌不出服务器）
      → 隔离的 Codex 任务执行环境
```

- 客户端 WebView 只获得本系统会话的安全投影及账户分配元数据；本系统 access/refresh token
  仅保存在桌面端本地 Java 进程内存中，可由后台撤销。上游 Codex access/refresh token 始终只在中央
  Java 服务端使用，既不会下发到本地 Java，也不会进入 Tauri 或 WebView。
- 停用用户、停用 Codex 账户或强制下线时，撤销服务器会话与相关活动任务。仅停止页面刷新不算强制下线。
- 不能将当前登录进程原样开放为可执行任意工具的远程 worker：同一身份下的 shell、文件读取、插件和调试接口可能读取凭据文件或进程内存。
- 任务环境必须与凭据保管隔离，限制挂载、进程可见性、身份权限和出站网络；禁止客户端获得通用上游 RPC、任意 URL 转发或凭据读取接口。
- 必须增加针对恶意工具调用、文件读取、进程调试、任务隔离与会话撤销的端到端测试，完成后才能宣称远程客户端接入可用。

如果产品选择“直接登录用户本机的官方 Codex”，上述不下发凭据目标不能成立。应明确改成用户自有账号登录，或接受本地凭据可被设备所有者取得的风险，不能承诺“绝对防逆向”。

### 如果接受本地凭据可被设备所有者提取

可另行实现的保护方案（**尚未实现，待产品确认安全边界**）：传输强制 HTTPS；每台设备独立密钥加密交付，私钥放系统凭据库；仅在受控本地进程内使用，避免明文 JSON 落盘；上游刷新凭据留在服务器，业务会话绑定用户与设备，禁止任意账户选择和凭据导出。是否能只交付 access token 必须依据部署版本官方接口验证，不能假定实验性接口可用于生产。

这些措施防护的是文件直接复制、网络窃听与意外泄露，不会使本地运行的上游令牌对设备所有者不可见。客户端退出或后台强制下线，只能立即撤销本系统会话，不能因此承诺已经下发的上游 token 同时失效；必须另有上游撤销机制或等待其实际过期。服务端自设的短租约也不能缩短上游令牌本身的有效期。

## 本轮验证范围

- 管理后端 `mvn verify`：87 项测试，0 项失败/错误，其中 2 项需要真实官方登录而默认跳过；覆盖团队与个人策略优先级、会话失效、未知用量阻断、账户重分配、禁用团队/账户以及原有授权和凭据保护。
- 客户端 Java：26 项测试通过；客户端界面：16 项测试、类型检查和桌面构建通过；Tauri/Rust 测试和格式检查通过。
- 管理前端：47 项测试、类型检查、生产构建通过，包含团队与个人额度表单行为测试。
- 本机中央 Java 服务、管理网页和桌面客户端均已启动；未认证的新团队和个人额度接口返回 `401`。没有在登录后的浏览器完成真实账户授权或端到端 Codex 任务验证。
- 尚未使用真实 OpenAI 账户完成授权入库；需要管理员本人在官方网页确认。服务器任务执行及可靠逐人用量采集未实现，不能对生产服务器或远程客户端宣称安全验收完成。
