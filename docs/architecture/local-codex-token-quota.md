# 本机官方登录与个人 Token 统计

## 用户旅程

- 管理员在每位用户的电脑上，通过官方 ChatGPT 桌面应用和/或 Codex CLI 手动完成官方登录。
- 用户打开 Quota Guard 桌面客户端，使用**本系统账户**登录；本系统不负责官方登录，不保存或下发官方凭证。
- Windows Rust 服务从该操作系统用户的默认 `~/.codex` 读取 Codex 会话日志，按事件 ID 幂等上报 `totalTokens` 到中央 Java 服务；客户端关闭后服务仍可工作。扫描游标放在 Quota Guard 自己的数据目录，绝不写入官方登录目录。服务未安装时，客户端打开期间仍有 Java 扫描回退。
- 用户在客户端登录本系统账号时，中央服务为该 Windows 用户对应的设备颁发**仅可上报用量与心跳**的设备令牌；Rust 服务接收后保存于受限的 ProgramData 目录。设备令牌不是官方 Codex 凭证，不能用于普通用户或管理员 API。同一设备 ID 不允许改绑其他系统用户。
- 中央服务按系统用户统计个人用量，并将每笔事件归属到上报时的团队。个人额度与团队共享额度分别计算；团队另有从上次重置后累计的总 Token 上限。5 小时上限为 `null` 表示不设限，`0` 表示额度为零。旧百分比字段不换算为 Token。
- 客户端通过本机官方 Codex app-server 的 `account/read` 和 `account/rateLimits/read` 读取可用的官方额度窗口，只把套餐、百分比、重置时间等安全摘要发到中央服务。管理员在“额度查看”页面看到团队共享用量、用户个人用量；在“官方账户”页登记估算总 Token 和负责上报的系统用户，查看其最近一次官方额度快照。

## 数据归属与展示

| 数据 | 来源 | 存放位置 | 使用方式 |
| --- | --- | --- | --- |
| 官方登录凭证 | 用户在官方应用登录 | 官方应用自行管理的本机存储 | Quota Guard 不读取、复制、下发或覆盖 |
| 官方额度百分比 | 官方 Codex app-server | 客户端读取，中央只存安全摘要和时间 | 参考展示；只显示官方实际返回的窗口 |
| 个人 Token 事件 | 本机 `sessions/*.jsonl` | 中央 Java 服务 | 校验时间后按事件发生时间滚动统计，接收时间保留用于审计 |
| 团队/个人 Token 上限 | 管理员 | 中央 PostgreSQL | 分别计算团队共享与个人剩余量；团队累计总额从重置后持续累加 |
| 设备心跳 | Windows Rust 服务 | 中央 PostgreSQL | 管理员查看在线/离线与最后上报时间 |
| 计费服务运行日志 | Windows Rust 服务 | 本机受限的 ProgramData 日志目录 | 查看配对、扫描、上报、心跳和固定错误码；不保存凭证或原始会话行 |

Rust 服务优先采用会话中的 `token_usage_record`；Java 回退扫描器还支持旧日志中累计 `total_token_usage` 的正增量回退。两者均不重复累加输入、缓存或推理子字段。首次启用时只用文件元数据和 4 KB 前缀建立当前日志基线，不解析此前大量历史、不把先前历史计给新登录的系统用户。上报失败时 Rust 游标不前进，之后以相同事件 ID 重试；中央端按系统用户去重。

用量事件同时上报日志中实际存在的模型、思考等级、输入、缓存读、缓存写、输出和思考 Token 分项。输入已包含缓存，输出已包含思考；个人和团队额度始终只扣一次 `totalTokens`。管理端“用量统计”提供汇总、趋势、分布、筛选、分页流水和模型定价；桌面端“用量统计”只查询登录系统用户的近 24 小时、7 天或 30 天数据。金额统一为 USD，按 CC Switch 快照或管理员覆盖的每百万 Token 单价估算，与官方订阅额度百分比分开。旧记录缺少分项时保留未知，不回填零。详见 [Token 分项统计与 USD 费用估算](usage-pricing.md)。

Rust 服务会在上报前解析事件时间，跳过超过 29 天或超前 4 分钟的记录，并提交相应扫描游标。中央服务拒收超过 30 天或超前 5 分钟的事件；跳过这些本来无法入库的记录，可避免旧日志反复使后续有效上报卡住。开发启动脚本每次先构建计费服务，检测到安装版本与新构建不一致时请求管理员授权升级，沿用原设备绑定和扫描状态。

V12 为已接收事件补充团队归属：历史事件只能按迁移时用户所属团队回填，之后的新事件按接收时所属团队固定归属，换队不会改动旧团队用量。V13 让删除用户时保留已接收事件及其团队用量，直到滚动窗口自然结束。

Rust 运行日志为 `%ProgramData%\CodexQuotaGuard\Meter\logs\meter.jsonl`，每个文件最多 2 MiB，另保留 `meter.1.jsonl` 至 `meter.5.jsonl` 五份备份。它只写入固定事件类型、状态、上报批次的事件数/Token 合计、心跳和安全错误码；设备令牌、官方凭证、响应 ID 和原始 JSONL 均不得写入。中央 `codex_usage_events` 是成功接收的逐笔用量记录，不能把本机运行日志当作权威账单。已安装的旧版服务需要重新安装新构建的可执行文件才会生成此日志。

## 状态与限制

- 本系统账户未登录且 Rust 服务尚未配对：不向中央上报，也不读取官方额度。已配对 Rust 服务独立于客户端进程，即使用户退出或关闭 Quota Guard，仍会继续扫描并上报至原绑定系统账户；管理员可撤销该设备令牌。
- 官方账户未登录或 CLI/app-server 不可用：个人 Token 统计可继续，官方额度显示“暂不可读取”；管理后台保留上次上报时间，不应把旧值当实时值。
- 5 小时上限未设置时该窗口不设限；7 天基础额度缺失或已设置的额度用尽时客户端提示用户及管理员；**不会退出或拦截官方 ChatGPT/Codex 应用**。
- 团队策略停用后，个人统计仍继续接收可读取的本机 Token 事件，避免官方客户端继续使用时出现统计缺口。
- 仅能统计本机可读取且格式受支持的 Codex 会话日志。Windows 服务可减少关掉 Quota Guard 引起的遗漏，但本机管理员仍可停止服务、修改日志；官方客户端未写出可读日志、使用其他系统账户/设备也可能遗漏。Windows 服务控制管理器提供开机自动启动及进程失败后的恢复，不是防篡改驱动；此模式不能提供不可绕过的逐人硬限额。
- 当前 Rust 常驻服务只实现 Windows；macOS/Linux 仍需各自的 `launchd`/`systemd` 安装器与验证。服务每约 30 秒上报心跳，后台显示最后心跳及过期状态。服务掉线只会在本系统告警，无法阻断官方 Codex 使用。
- Windows 服务安装后随系统自动启动。桌面程序启动时若发现服务停止，会尝试拉起；权限不足时 Windows 会要求一次管理员确认。拒绝 UAC、服务被禁用或尚未安装时不会伪装成“正在计费”；关闭客户端不停止已启动的服务。
- Windows 原生 Codex CLI 与 Codex 桌面应用通常使用 `%USERPROFILE%\.codex`；WSL、macOS、Linux 的用户目录互相独立。本机服务只扫描当前操作系统用户的默认目录，若使用自定义 `CODEX_HOME`，须显式设置 `QUOTA_GUARD_OFFICIAL_CODEX_HOME` 与之对应。

## 迁移与安全

- V9 在**已验证受保护备份后**解除历史事件与托管账户的关联，保留个人 Token 事件，清除活动 PostgreSQL 库中的旧托管账户、加密凭证及旧百分比快照。V10 新增按系统用户保存官方额度安全摘要的表。
- 旧“授权添加 Codex 账户”“团队分配托管凭证”“凭证下发”“客户端登录 Codex”接口和入口均已停用。新的“官方账户”页只登记只读额度快照的来源与估算 Token，不是托管登录或请求路由。旧版本客户端须升级，否则可能调用不存在的接口。
- 数据库备份中仍包含历史加密凭证，必须限制访问并按保留策略销毁；备份不是可继续运行的托管账户功能。
- 正式部署仍须为中央服务启用 HTTPS。当前允许的局域网 HTTP 仅供受信任的开发环境，系统密码与会话会明文经过网络。

官方接口参考：[Codex app-server](https://learn.chatgpt.com/docs/app-server)、[Codex 身份验证](https://learn.chatgpt.com/docs/auth)。
