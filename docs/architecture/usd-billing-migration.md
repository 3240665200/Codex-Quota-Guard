# USD 额度改造

用户已确认：历史用量按升级时的价格表回算 USD 并标明回算；旧 Token 上限保留，新美元上限重新配置，NULL 表示无限制，0 表示额度用尽。

## 实现约定

- Token 保留为计量与审计明细。团队、个人、官方账户的预算、已用、剩余、进度条和限制判断全部以 USD 为准。
- 每笔事件只入账一次，金额使用 DECIMAL / BigDecimal；快照保存输入、输出、缓存读写单价和倍率。调价不改变已入账金额。
- 普通输入 = input - cached input - cache write。reasoning output 已包含在 output，不重复收费。
- 快速模式以该笔事件或对应轮次的实际 service_tier 为依据，fast / priority 按用户指定的默认 1.5 倍；后台价格表可调整倍率，不能拿推理强度推断速度模式。
- 历史缺失模式标记的记录按普通费率回算，必须标明模式未记录；缺少价格或 Token 拆分的记录显示待核算，不能伪装成 0 美元。
- 当前 Codex 标准日志未提供速度字段。新用量缺少明确模式时默认待核算，不猜测普通或快速。管理员可按设备设置从当前时间起的普通/快速计费声明，或选择尚未入账的流水明确确认模式；保存依据及操作者，已入账金额不可改写。设备设置保存在服务器，客户端退出不影响后台服务上报和计费。切换 Codex 快速模式时须同步设备声明；声明并非官方模式验证。
- 官方套餐百分比是独立参考，不能换算成美元余额。官方账户预算由管理员填写，账户消耗按事件接收时关联的官方账户归集；历史归属按升级时团队关联回填并标明来源。
- 数据库使用新增列与账本，不修改已发布迁移、不覆盖旧 Token 配置。老 Token 配置不再参与新的额度拦截。
- 个人额度定时检查支持 1～1440 分钟，默认 1 分钟；更改设置后重新安排下次检查，保留官方限流、租约和不确定结果保护。

## 验证范围

价格快照、历史回算、重复上报幂等、缓存与推理 Token 不重复计费、快速模式倍率、空上限/零上限、个人/团队/官方账户归属、调价与待核算记录、检查间隔持久化与重启恢复，以及后台、桌面前端和独立 Rust 统计服务的完整链路。
