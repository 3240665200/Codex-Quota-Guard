# 当前系统架构

本文描述当前代码，不把规划中的能力写成已上线功能。项目是一个 monorepo：`apps/admin` 是中央管理系统，`apps/client` 是用户桌面端；Java 17 仍是两端的业务后端，Rust 用于 Tauri 壳和独立统计程序。

## 运行组件

```text
官方 Codex CLI / 桌面应用
       │ 本机 .codex/sessions/*.jsonl
       ▼
Rust Windows 统计程序 ──设备令牌、用量事件、心跳──▶ 中央 Java API ──▶ PostgreSQL
       ▲                                            ▲
       │ 首次配对                                   │ 系统用户、团队与额度策略
React/Tauri 桌面端 ──回环 API──▶ 本地 Java 服务 ────┤
                                                    │
Ant Design Pro 管理页 ─────────管理员 API────────────┘
```

| 组件 | 代码位置 | 职责与生命周期 |
| --- | --- | --- |
| 管理页 | `apps/admin/frontend` | 管理系统用户、团队、个人 Token 上限、只读官方账户登记；查看用量、官方额度摘要和设备心跳。 |
| 中央 Java API | `apps/admin/backend` | Spring Security 鉴权、PostgreSQL/Flyway 持久化、幂等事件入库及额度计算；独立部署。 |
| 桌面界面与 Tauri 壳 | `apps/client/frontend` | 本机登录界面与仪表盘；Tauri 仅向本地 Java 转发固定命令，并管理 Java 子进程。 |
| 本地 Java 服务 | `apps/client/backend` | 只监听回环地址；内存中维护本系统会话、配对统计程序、读取本机官方额度摘要；托盘隐藏时保留，随客户端真正退出结束。 |
| Rust 统计程序 | `apps/client/meter` | Windows Service，独立于桌面窗口运行；增量扫描本机 Codex 会话日志，发送用量与心跳。 |

管理页开发端口默认 `8000`，中央 API 默认 `8080`。桌面本地 Java 使用随机回环端口，不向局域网开放。管理端生产部署应通过 HTTPS/反向代理暴露中央 API；开发阶段允许受信任局域网 HTTP，但会明文传输本系统密码和会话。

## 两套身份与两种额度

1. **Quota Guard 系统账户**：本项目用户、管理员和团队使用。桌面端登录后，本地 Java 向中央 Java 获取本系统会话；管理员的强制下线只使本系统会话失效。
2. **官方 Codex 登录**：用户在官方应用或 CLI 中自行完成。Quota Guard 不托管、分发或覆盖官方会话凭据，也不替用户登录官方 ChatGPT 桌面应用。可选的[登录辅助](./login-assistance.md)由中央 Java 读取管理员自有邮箱，为所属团队用户提供新邮件中的登录验证码；邮箱授权单独加密，不进入桌面端或统计程序。
3. **官方额度**：本地 Java 通过 Codex app-server 的 `account/read` 与 `account/rateLimits/read` 读取账户级套餐、窗口百分比和重置时间，只上报安全摘要。官方没有返回的窗口不得推算或伪造。
4. **团队共享与个人 Token 额度**：管理员填写团队共享的滚动 5 小时、7 天上限和独立累计总额，并可为用户设置独立的个人窗口上限。个人剩余只扣个人用量，团队剩余只扣成员归属该团队的用量；任一已设置的额度用尽，本系统就标记受限。5 小时 `null` 表示不设限，`0` 是零额度；7 天基础额度仍需配置。这些 Token 值不能由官方账户百分比精确换算。
5. **只读官方账户登记**：后台只保存账户名称、管理员输入的估算总 Token 和一位负责上报的系统用户。团队关联该登记账户后，累计上限与估算值同步。额度快照来自该用户本机的官方登录，中央服务不保存官方凭证、不代为登录，也不能验证快照一定属于登记的账户名称。

## 配对与用量统计数据流

1. 安装程序本身不注册服务。用户以该 Windows 用户身份右键“以管理员身份运行”桌面程序。若 `CodexQuotaGuardMeter` 尚未安装，桌面端会验证打包资源并执行捆绑的安装脚本；0.2.12 起该步骤可离线完成。脚本固定该用户的 `.codex` 目录，创建设备 ID，并把服务设为自动启动及异常退出后恢复。权限不足或资源缺失时不执行安装；修正后可从仪表盘重试。Windows 原生程序静态包含 C 运行库，打包阶段检查 DLL 导入以防依赖未随包安装的 VC++ 运行库。失败步骤记录在用户数据目录的 `meter-setup-status.json`，仅含状态、步骤和时间。已注册但无法启动的服务可以用随包文件修复，保留原设备和游标。
   桌面程序以后启动时会查询统计程序的 Windows 服务状态，已安装而停止则自动尝试启动；无 `SERVICE_START` 权限时通过 UAC 请求管理员授权启动固定服务。用户取消授权时保留明确诊断，不会静默改动服务权限。0.2.17 起关闭主窗口只隐藏到托盘，系统登录和本地 Java 服务保持；通过托盘“退出客户端”才结束本地 Java 子进程，不结束已启动的 Rust 统计程序。Windows Job Object 只绑定当前实例启动的本地 Java 子进程，客户端意外退出时也释放此子进程。
2. 用户登录桌面端的系统账户。本地 Java 使用系统 access token 调用中央 `/client/meter/enroll`，取得仅可访问 `/meter/**` 的设备令牌，并通过本地配对收件箱交给 Rust 统计程序。中央数据库只保存设备令牌 SHA-256 摘要；Rust 将令牌放在受限的 ProgramData 目录。一个设备 ID 不能自行改绑另一系统用户，撤销后也不能自行恢复。
3. Rust 统计程序首次启用与首次配对只建立旧日志的字节游标，不追溯既往用量。之后优先读取新增 `token_usage_record.total_tokens`，生成不含原始响应 ID 的稳定事件 ID。每批至多 100 条；上报成功才提交扫描游标，失败则保留游标重试。
4. 中央 Java 校验设备令牌、事件格式和时间，按系统用户与事件 ID 去重，存入 `codex_usage_events`，并固定事件接收时的团队归属。5 小时/7 天窗口按**经过校验的事件发生时间**分别汇总个人与团队用量；团队累计总额从上次重置后计算。接收时间用于审计和最近上报状态。成员换队不转移旧用量，删除成员也不退回团队已用量。Rust 每约 30 秒发送心跳；管理员可见最后心跳与在线/离线状态。
5. 桌面窗口关闭后 Rust 统计程序仍可继续上报。统计程序状态为 `UP_TO_DATE` 或 `REPORTED` 且文件无需兼容扫描时，Java 扫描器进入 `SERVICE_ACTIVE` 待命，不移动回退游标。Java 每轮仅检查元数据与至多 4 KiB 前缀；新文件、文件替换、旧格式追加或待处理累计记录仍会触发兼容扫描。统计程序离线或异常时恢复回退，并兼容部分旧版 `token_count` 累计记录。中央去重防止同一事件重复计算。

## Windows 桌面自启动

桌面“设置”页通过固定 Tauri 命令 `autostart_status` / `autostart_set` 查询及修改自启动，接口只接受启用/禁用 Boolean，不接受外部程序路径、命令或账户。打开设置页、重新聚焦窗口或恢复页面可见时重新读取 Windows 状态，查询不自动写入。读取失败、保存失败与不支持的平台均明确提示。

Windows NSIS 安装包保持 currentUser 范围，允许自选目录。POSTINSTALL 仅显示说明，不调用客户端登记启动项。正式版每次启动在构造 Tauri 之前检查当前 TokenUser、桌面用户 SID 和 TokenElevation；首次获得当前用户管理员权限后才默认登记。0.3.7 起，非管理员的普通启动和登录启动都进入同一条 `ShellExecuteExW(runas)` 流程；原启动器退出，仅已获权限且身份一致的子进程继续。开发版不自动登记依赖 Vite 的启动项。初始化失败显示固定的原生提示，不把失败当成成功。

普通启动项使用 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的固定值 `Codex Quota Guard`，内容仅为带引号的当前主 EXE 绝对路径加 `--autostart-launch`，不会执行来自注册表的任意命令。命令须符合 Windows Run 的长度限制。未提权的短时启动进程只调用 `ShellExecuteExW(runas)` 启动自身固定的 `--autostart-elevated` 模式，然后退出；使用 `SEE_MASK_NOASYNC` 等待 Shell 提交操作。取消 UAC 不创建 Tauri/Java/统计守卫，提权子进程再次检查同 SID 与管理员权限，拒绝其他管理员凭据。发布版本地 Java 只运行捆绑 JAR，屏蔽注入 Java agent 的环境变量。

任务管理器禁用普通启动项时可能保留 Run 命令，因此同时读取 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run` 的同名状态。关闭时保留 Run 登记，方便用户在任务管理器重新开启；显式开启才清除本项禁用标记。对已识别的 12 字节状态只接受 0/2 为开启、3 为关闭，未知格式报错且不改写。该二进制格式没有微软公开稳定契约，实现参考 [Electron 的 Windows 登录启动处理](https://github.com/electron/electron/blob/main/shell/browser/browser_win.cc)，仍需在支持的 Windows 版本验收。Run 机制及长度限制见 [微软文档](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)。

迁移仅处理精确匹配当前 SID、本安装目录、URI、固定参数、单个登录触发器和执行动作的旧 LUA/Highest 任务；账户名仍经 Windows 解析为 SID 后比较。新启动项若已存在，以其 Windows 实际状态为准，否则保留旧任务的开关。迁移分阶段登记、禁用旧来源、验证新状态并删除旧任务，失败尝试恢复原状态，恢复失败明确提示，不宣称原子事务。不同目录或身份不符的记录不会覆盖。偏好按 SID 保存在本软件 HKCU 项；仅从旧 HKLM 偏好读取 Boolean，不恢复任意路径。卸载只清理本安装的启动项及已验证的旧任务，保留开关偏好；`/UPDATE` 保留现有状态。整个流程不安装、停止或卸载独立统计服务。

主 EXE 需保持默认 asInvoker 兼容性设置；若用户永久勾选 RunAsAdmin，普通启动项可能在进入主函数之前就被系统阻止。UAC 弹窗仍受系统安全策略影响，不承诺绕过授权或自动提升标准用户。macOS/Linux 当前不提供此自启动设置。真实安装、任务管理器联动及注销重新登录流程需在目标电脑验收；自动化通过模拟注册表/计划任务和安装脚本编译验证，不修改真实系统启动项。

已有普通启动项的状态查询只读注册表；没有普通项时会读取旧任务的真实状态，避免迁移失败后误报关闭。初始化、显式设置及卸载仍核验旧任务以防重复入口，因此这些操作在 Windows 任务计划程序不可读时会保守报错，不会忽略旧记录继续写入。

## Windows 安装与旧版本衔接（0.3.5）

应用身份保持 `Codex Quota Guard` / `com.codexquotaguard.desktop`，发布者固定为 `codexquotaguard`。NSIS 安装范围保持 currentUser，允许自选目录；范围切换不等于产品换名，但只读取 HKCU 的安装器无法发现 HKLM 中的旧 perMachine 安装。

源码中的兼容模板在安装器初始化时读取 HKCU/HKLM 的安装记录，区分共享视图和机器范围的独立 32/64 位视图，交叉验证版本、路径和程序产品信息。NSIS 升级只使用本产品固定注册表项；另保留名称和发布者精确匹配的历史 MSI/其他安装器冲突检测，发现后提示手动处理，不执行其注册表命令。当前用户安装默认保留原目录；跨范围迁移在选定目标目录、显示旧版信息并确认后进行。实际卸载前重新读取系统状态，使用固定路径下的 `uninstall.exe` 和固定参数，绝不执行注册表中的任意 `UninstallString`。临时检测结果只用于展示，不是卸载授权依据。

跨范围迁移使用旧版正常卸载流程，以便记录自启动开关并移除指向旧目录的任务；不使用会保留旧任务的 `/UPDATE`。卸载保留用户数据和统计服务。UAC 取消、非零退出、旧主程序或卸载记录残留均阻止后续文件安装。当前用户卸载项在两种视图中属于同一条共享记录（见 [Windows 注册表视图规则](https://learn.microsoft.com/en-us/windows/win32/winprog64/shared-registry-keys)），检测时去重，不按视图删除它；新安装完成后只验证写入结果。多份安装、路径异常或记录冲突不自动合并。

模板固定基于 Tauri CLI 2.11.5，修改点及上游来源随模板保存；升级打包工具时必须复核模板。自动化测试覆盖真实 PowerShell 策略的模拟系统输入及完整 NSIS 模板编译，不执行真实安装器、卸载程序或写入真实注册表。目标电脑上的 UAC、旧版本覆盖、目录迁移和数据保留仍需安装验收。已发布的 0.3.4 不包含本节新增的兼容修复，必须重新构建安装包。

## Windows CC Switch 冲突守卫（0.2.20）

Windows 桌面客户端每次启动先经过管理员门禁；只有客户端保持活跃且 Rust 统计服务核验本机 lease 有效时，统计服务才检查冲突进程。目标必须与客户端属于同一 SID、同一 SessionId，并被精确识别为 CC Switch，才会被强制结束；这不会触发 CC Switch 的正常退出流程，未保存的数据可能丢失。关闭主窗口并留在托盘不等于退出客户端；从托盘退出后 lease 失效，已启动的 Rust 统计服务仍继续运行与上报。

守卫检查独立于扫描和网络上传，启动门禁读取独立状态文件，避免大量用量上报拖慢检测。守卫失败时暂停后续上传和游标提交；已经发出的请求无法撤回。状态新鲜度容差为 30 秒，服务停止或崩溃后，客户端可能在这个时间窗口加下一次轮询间隔内才关闭本地 Java。

统计程序 0.2.2 配合新版桌面端增加强制终止通知：独立守卫状态文件保留当前 lease 的终止 epoch、累计已确认终止进程数与最后时间，不因下一轮变成 `CLEAR` 而丢失。桌面端每次读取有效守卫状态后按 epoch/计数去重，后台监控不依赖前端页面可见性；即使隐藏到托盘、未登录系统账户或本地 Java 启动失败，也由桌面 Rust 线程显示需要用户确认的 Windows 原生警告框。提示说明终止原因、未保存更改风险和检查官方直连配置的方法。

提醒使用单独线程，不阻塞守卫检测或续期；短时间内多次终止会合并进程数量，后续新事件仍会再次提示。显示失败保留待提醒事件并重试，退出客户端后不再调度新提醒。通知仅在用户的交互会话中显示，不使用 Session 0 服务弹窗；锁屏、系统安全桌面、客户端退出/崩溃以及无法写入状态文件等情况不提供即时交付保证。旧版统计服务没有累计字段，兼容提示只能尽力捕获；必须随新安装包升级到统计程序 0.2.2 才具备完整的防漏提醒能力。

进程识别无法保证覆盖所有 CC Switch 变体，也不能防止具备本机控制权的用户绕过；此守卫仅针对 Windows，不限制官方 Codex 请求，也不适用于 macOS/Linux。强制结束 CC Switch 不会自动恢复官方直连，也不能证明用量属于后台登记的官方账户。自动化测试使用模拟进程；实际 UAC 与结束真实 CC Switch 的流程需在目标测试机验收。

## 日志与排障

新构建的 Rust 统计程序将安全摘要写到 `%ProgramData%\CodexQuotaGuard\Meter\logs\meter.jsonl`，轮转文件为 `meter.1.jsonl` 至 `meter.5.jsonl`。单文件上限 2 MiB，总占用约 12 MiB；轮转时最旧备份会被删除。日志记录启动/正常停止、基线、配对前状态、成功上报的事件数和 Token 合计、心跳及固定错误码；**不写入官方凭证、设备令牌、原始会话行或响应 ID**。日志目录继承统计程序状态目录的 SYSTEM/Administrators ACL。安装旧版的电脑必须重新构建并升级统计程序，源码更新不会自动替换运行中的可执行文件。
同一错误持续出现时最多每 5 分钟重复记录一次，避免日志刷屏；公开状态快照写入失败也会在受限日志中留下固定错误码。查看脚本会忽略损坏行及未知字段，不回显原始 JSON。

桌面用量页面分开显示已入库的个人流水和统计程序运行诊断，记录每 10 秒更新。当前用户查询由中央 JWT 主体确定，不允许选择其他用户；客户端查询缓存按系统用户隔离。最近上报优先使用 Rust 公共状态时间，后台最近接收使用中央记录时间，不能把扫描时间当作入账时间。
本机 Java 仅从固定 ProgramData 日志文件（当前文件与 5 份轮转文件）各读取最多 64 KiB 尾部，投影最近 50 条固定摘要。读取不改变 ACL，权限不足会明确提示管理员运行；日志批次 Token 不等于新增入账量，后台重试去重后可能不会增加流水。

模型与思考等级仅从 `turn_context` 或用量事件的显式选择字段采集，按 `turn_id` 的散列关联，优先使用事件本身的字段。每个文件的游标保存至多 256 个安全回合上下文，跨扫描/重启保持关联；未知回合不会借用另一个回合的最新配置，不保留其他上下文内容。统计程序与回退扫描的新字段缺失时使用空值，不改变事件 ID、Token 总数或中央去重键。

管理员 PowerShell 可查看最近记录：

```powershell
& .\scripts\windows\show-meter-logs.ps1 -Tail 50
& .\scripts\windows\show-meter-logs.ps1 -Tail 50 -ErrorsOnly
Get-Service CodexQuotaGuardMeter
```

桌面端的 `meter-status.json` 只是当前状态快照；中央 `codex_usage_events` 才是已接收的逐笔事件。管理员可在“额度查看 → 用户详情 → Token 用量流水”中分页查询指定系统用户的入库记录，流水按服务端接收时间倒序；普通用户无权读取。Windows 事件查看器的 Service Control Manager 记录启动和异常退出，不包含逐笔 Token 数据。

统计程序版本独立于桌面客户端版本。桌面端可核对运行版本、已安装版本与安装包内版本；程序文件是否需要升级仍以 SHA-256 比对判定。升级只影响后续采集，不会自动补齐旧版未采集的流水或 Token 分项。

## 不能保证的事

- 官方 Codex 请求不经过本系统，所以个人额度用尽只触发本系统提醒，**不能硬性阻断官方 Codex 或让官方会话下线**。
- 管理员/root 可以主动停止统计程序的系统服务或修改本机日志；服务恢复策略只应对进程意外退出，不能防止管理员停用。没有跨平台通用内核驱动，也不承诺防篡改统计。
- 只能统计本机可读取且格式受支持的 Codex 会话记录；普通 ChatGPT 桌面聊天、其他设备或自定义 `CODEX_HOME` 不一定包含在此统计中。官方额度是账户级参考，不是个人账单。
- Windows Service 已实现；macOS `launchd`、Linux `systemd` 的常驻安装器尚未实现。尚未完成设备配对和新用量的实际入库验证时，仪表盘的 0 Token 不代表真实使用量为零。
