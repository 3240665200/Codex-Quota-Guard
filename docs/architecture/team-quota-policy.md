# 团队与个人额度策略

## 身份与数据边界

- 系统用户使用本系统的登录会话；Codex 账户由管理员统一授权并保存在中央 Java 服务端。这两种账户不能混用。
- 管理员可将系统用户加入一个团队、分配一个启用的 Codex 账户，并设置个人额度覆盖值。团队提供默认策略，不直接拥有或分发上游凭据。
- 桌面客户端只读取当前系统用户的团队、有效策略和安全账户摘要；不接收 Codex `auth.json`、access token、refresh token、加密密文或解密密钥。

## 策略解析

额度使用 5 小时主窗口与 7 天次窗口的百分比上限，均为闭区间 `0..100`。每个窗口独立按以下优先级计算：

```text
个人覆盖值 → 启用团队的默认值 → 系统默认值 100%
```

`null` 表示继承下一层，`0` 表示该窗口不允许使用。团队被禁用、系统用户被禁用、分配的 Codex 账户被禁用或缺失时，不允许受控执行。策略变更应使受影响用户的旧会话失效，避免客户端继续使用过期授权。

## 用量来源与限制

官方 Codex 的 `account/rateLimits/read` 提供的是上游账户的窗口快照，并不是共享该账户的每个系统用户各自消耗。不能把账户使用率复制给每个用户当作个人用量，也不能把未知用量显示成 `0`。个人用量只能在中央服务受控执行 Codex 任务时，按系统用户身份逐次记账；客户端无用量写入接口。

客户端的服务端用量响应区分 `CURRENT` 与 `NOT_MEASURED`。尚未接入受控执行和可靠计量时，用量与剩余量为 `null`，界面显示“尚未采集”。已有测量超过 5 分钟、账户变更或窗口重置后也变为未采集。未来的执行入口必须在服务端检查登录会话、团队和账户状态、有效策略、测量新鲜度及剩余额度；未知或过期的用量必须拒绝放行，不能用展示层判断代替服务端约束。

因此，配置一个百分比阈值不会创造新的 Codex 容量，也不会自动把一个共享的上游账户拆成相互独立的个人配额。完整的按人额度执行，还依赖后续的服务器隔离任务执行与计量链路。

官方协议参考：[Codex App Server `account/rateLimits/read` 类型](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/account.rs)。
