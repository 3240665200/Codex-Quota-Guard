# 限制管理

管理后台的“限制管理”提供两条独立规则，初始均关闭。保存启用后由中央服务器执行，桌面客户端和管理网页不需要保持打开。

## 个人额度用尽下线

每 30 秒检查仍有效的官方会话绑定。只按该用户已设置的个人 5 小时、7 天 Token 上限判断；留空为无限制，`0` 表示无可用额度。达到任一上限后，对精确匹配的官方会话 ID 发起撤销请求，并在官方接受或结果不明确时使对应本地绑定失效。

团队共享额度和官方百分比不触发这条个人规则。已绑定的受信任设备仍受个人额度约束；当前官方管理会话及身份状态未知的设备受到保护。绑定、团队、授权版本或个人额度在执行前发生变化时，旧任务取消。

## 未绑定会话清理

默认每 **90 分钟**检查一次，可设置为 30～1440 分钟。启用或改变间隔后从新的计划时间开始检查；已保存的检查时间在服务重启后继续生效。

保留官方标记的当前设备、受信任设备、有效绑定、缺少/重复会话 ID，以及当前/信任状态未知的设备。账户正在登录、绑定、恢复或处理其他下线任务时延后检查。

## 执行与记录

- 规则保存在 `restriction_policy`，管理员修改带版本校验。
- 各账户的检查时间、数据库任务租约和官方冷却截止时间保存在 `restriction_account_checks`，多实例不能重复派发同一任务。
- 自动操作复用官方下线的持久执行记录和账户互斥锁；规则关联和执行审计在发请求前一并入库。
- 发送前再次核对规则版本、绑定、额度、官方身份和目标设备。自动规则不会调用“登出所有会话”。
- 官方 `Retry-After` 会跨重启、设置变更继续生效。已发出但结果不确定的请求保持账户执行屏障，必须在“官方账户 → 会话管理”核对，不自动重发或自动解除屏障。
- “已接受请求”表示官方受理，官方会话列表可能稍后更新。统计服务继续上报已采集用量，不因客户端失去绑定而丢弃记录。

## API

仅管理员可调用，响应使用 `Cache-Control: no-store`：

- `GET /api/v1/admin/restrictions`：设置、账户检查状态和最近 20 条执行记录。
- `PUT /api/v1/admin/restrictions`：保存两个开关、未绑定检查间隔和已读取的设置版本。修改遵守部署的管理传输策略。

新增数据库迁移 V37。升级不自动启用规则，不修改现有额度、绑定或用量数据。
