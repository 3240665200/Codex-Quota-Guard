# 当前桌面源码的启动与独立统计测试

本指南针对 `0.3.25` 源码和统计服务 `0.2.6`。新安装包保存在 `dist/desktop-v0.3.25`；项目内较早生成的 `dist/desktop-v0.3.24` 安装包仍含旧 Java 架构。

## 启动界面

1. 从系统托盘完全退出旧客户端。只关闭主窗口可能仍在托盘运行。
2. 在 `E:\project\pingche` 打开普通 PowerShell，首次执行 `pnpm install`。
3. 双击项目根目录的 `一键启动-桌面客户端.cmd`，或执行 `pnpm dev:client`。
4. 登录页保存中央服务器地址，再登录系统账户。正常打开桌面不要求管理员权限，开发启动不安装或修复服务。

如果已有客户端运行，开发启动脚本会明确提示退出旧版本，避免误把已安装旧程序当作当前源码。启动日志保存在项目 `dist/development-logs`。

中央后台也需要本次源码中的桌面 CORS 配置；仅启动新客户端、仍连接未更新的旧服务器时，请求可能被浏览器阻止。本机中央后台和管理网页可使用根目录 `一键启动-管理后台.cmd`，按启动窗口显示的实际地址填写。测试数据与正式数据要选对环境。

## 测试额度进度条与显示方式

后台“额度查看 → 用户额度”现在按每个用户的实际用量显示 5 小时、7 天个人额度进度条。打开后台侧栏“设置 → 额度显示”，可单选“剩余”或“已用”；桌面端在已有的“设置 → 显示设置 → 额度显示”中调整。

默认显示“剩余”。例如上限 100、已用 25 时，剩余模式显示 75 与 75% 的进度条，已用模式显示 25 与 25% 的进度条。个人、团队共享和官方额度的文字及进度条会一起切换，成员的团队用量占比仍表示实际贡献比例。不限额不生成百分比，读取失败不填成 0%。

两端分别在当前浏览器／本机保存显示偏好，刷新或重启后保留；它只影响展示，不修改额度策略、已计费用量或统计服务。0.3.25 本机安装包已包含这些功能；线上服务器需要单独更新。

## 测试官方额度与 Authenticator

使用当前源码同时启动中央管理后台和桌面界面。在管理网页“账户管理”先完成对应账户的官方授权与代理设置，再打开“额度检测”：默认 5 分钟，可设置 1～1440 分钟。点击“立即检测”后应显示官方返回的剩余比例和快照时间；冷却期间无法再次提交，刷新列表不会额外请求官方。

要测试 Authenticator，在同一账户行打开“验证器”，填写该账户已有的 Base32 TOTP 密钥或标准 `otpauth://totp` 链接并启用。后台需要沿用既有 `OFFICIAL_SESSION_ENCRYPTION_KEY`。将测试用户加入关联该账户的活动团队，登录桌面后进入“登录辅助”，点击“获取验证器验证码”。与手机在同一时刻对照；到期、切到后台或离开页面后应隐藏，未分配该团队的用户不能获取。不要在正式账户上为此重置双重验证或暴露密钥。

本机打包入口为根目录 `一键打包-桌面客户端.cmd`，已打包管理后台可双击 `一键启动-已打包管理后台.cmd`。这不会更新线上服务器；旧安装包和旧服务器不会自动具备新功能。协议与当前联调限制见[官方账户说明](official-account-management.md)。

## 准备当前统计服务

正式安装包会强制安装统计服务。当前仅做源码测试时，需显式准备一次，不由客户端偷偷安装：

```powershell
cd E:\project\pingche
pnpm --dir apps/client/frontend build:meter
```

构建完成后，在**当前 Windows 用户的管理员 PowerShell** 中执行，替换中央地址：

```powershell
cd E:\project\pingche
& .\scripts\windows\install-meter-service.ps1 `
  -ServerUrl 'http://你的中央服务器:8080' `
  -BinaryPath 'E:\project\pingche\apps\client\frontend\src-tauri\resources\meter\quota-guard-meter.exe'
```

这一步会实际安装或更新服务。已有服务会保留设备身份和计量状态；不要删除 ProgramData 中的队列来解决错误。安装后回到桌面登录系统账户，让它完成设备登记；在“统计程序”页确认运行版本为 `0.2.6`、最近扫描时间在更新。

## 验证客户端退出后继续记录

1. 确认服务已配对，并在中央后台确认该设备在线。
2. 从托盘选择“退出客户端”，让桌面程序完全退出。
3. 使用官方 Codex 应用或 CLI 完成一次会产生用量日志的请求。
4. 在中央管理网页查看新用量和设备心跳，或稍后重新打开客户端查看流水。后台约每 3 秒扫描日志，计入时间取决于官方日志何时写入和网络情况。
5. 可在 Windows“服务”中只读查看 `CodexQuotaGuardMeter` 的自动启动和恢复设置。主动手动停止服务不属于崩溃，测试后需要自行恢复。

首次配对只建立历史基线，不补算之前的日志。系统关机时无法实时采集；离线时已捕获的数据保存在本地，网络恢复后补传。重复上报依靠中央稳定事件 ID 去重。旧累计记录与晚到直接记录无法排除重叠时，会隔离保留并提示核对。

## 本次已做的隔离验证

测试使用生成的用户、设备、日志和回环服务，没有替换电脑中已安装的统计服务。验证包括慢 HTTP 时继续采集、断网后持久排队、删除测试源日志后重启补传、累计记录兼容与去重、地址修改失败回滚，以及安装器必需服务步骤。

原生统计程序的独立进程测试报告位于项目 `dist/meter-independence-0.2.6/production-meter-smoke-result.json`。客户端完全退出后的真实使用验收，仍按上面的步骤在你选定的测试环境完成。
