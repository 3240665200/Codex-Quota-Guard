## 实际页面验收

使用独立 PostgreSQL schema、合成管理员、文档保留 IP 节点及不可用于真实登录的合成授权记录。只在本机 8001/18081 运行 QA，未修改用户原有账户、订阅、节点或功能密钥。

- 正常启动、登录、手动添加节点、退出登录、精确停止和重启均通过；Flyway 在隔离 schema 完成到 V33。
- 重现系统 DNS 将 httpbingo.org 返回为 198.18.0.42 的问题；修复后经受限 DNS 得到真实公网 IP，并完成 TCP 与原域名 TLS 验证。
- 使用公共 HTTPS 回显端点承载不含真实密码的两条合成节点；实际页面首次导入与手动更新返回200。
- 修改订阅 URL 只显示待手动更新，未立即改变节点。更新后保留同名节点ID并更新地址，消失的前置节点停用且保留ID。
- 将导入节点设为前置、手动节点设为出口，单独保存链返回200；数据库确认两个引用正确、原合成授权保持原样，关闭再打开仍可恢复选择。
- 同一节点作为前置/出口被禁选；前置来源缺失时，测试链、保存链及官方刷新禁用，管理节点链接正确跳转。
- 移除订阅来源返回204；订阅数归零、三个节点仍在、账户前置引用及停用状态保留。
- 订阅 URL 未进入 localStorage/sessionStorage；列表不回显URL。
- 桌面、768px、375px 主页面没有页面级横向溢出，节点表格独立横向滚动。
- 预期的负向网络状态：无官方快照时409；主动重启期间一次用户校验504。成功导入/更新/保存/移除流程没有未处理的页面脚本异常。
