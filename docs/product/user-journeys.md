# Codex Quota Guard 用户旅程

## 管理员

- 管理员在 Web 后台创建团队，设置 5 小时和 7 天窗口的默认使用率上限，并管理团队的启停状态。
- 管理员创建系统用户，为其选择团队、分配一个后台托管的 Codex 账户；必要时可分别覆盖个人的两个窗口上限。
- 修改用户团队、个人额度或团队默认策略后，受影响用户的旧系统会话失效，重新登录后读取新策略。
- 管理员可以禁用用户、取消账户分配和强制下线。所有执行权限最终由中央 Java 服务校验。

## 系统用户

- 用户用本系统账号登录桌面客户端。系统账号与 Codex 账户是两种不同身份。
- 客户端显示自己的团队、管理员分配的 Codex 账户、有效额度上限、服务端测得的用量与剩余量。
- 上游 Codex 凭据始终保存在中央服务；客户端不进行本机 Codex 登录，也不接收其 JSON 或令牌。
- 服务端尚未测得用量时，界面明确显示“尚未采集”；未知值不能显示为 0，也不能用于放行受控执行。

## 用量与限制

- 每个窗口的有效上限按“个人覆盖值 → 团队默认值 → 系统默认 100%”解析。0% 表示该窗口不可使用。
- “上游 Codex 账户已使用百分比”是账户级总量。如果多个系统用户共享同一个 Codex 账户，不能将这个总量分别声称为每个人的消耗。
- 个人实际消耗必须由中央服务执行任务时逐人记账；客户端不能自行上报或修改。服务端执行入口要在任务开始前检查系统会话、账户分配、策略、测量状态及剩余额度。
- 当前未接入服务端 Codex 任务执行与逐人计量时，仅展示已配置的策略和真实可得的测量状态；不承诺已经能按人使用 Codex。

## 安全边界

- 禁用用户、强制下线或变更分配后，中央服务立即拒绝旧系统会话。
- 管理员界面、客户端及日志都不返回上游 Codex 凭据。客户端只访问固定白名单接口。
- 对于未知或过期的用量，受控执行入口按不可用处理；页面展示不能替代服务端限制。
