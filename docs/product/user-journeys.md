# Codex Quota Guard 用户旅程

## 房主

- 作为房主，我希望创建一个可放在 OneDrive、Dropbox、NAS 或局域网共享盘中的房间，以便任意数量的成员加入。
- 作为房主，我希望为每名成员分别设置 Codex 主窗口（通常为 5 小时）和次窗口（通常为 7 天）的最大已用百分比。
- 作为房主，我希望策略带有数字签名，以便成员端只执行真正由房主发布的强制下线策略。
- 作为房主，我希望看到每名成员的最后更新时间、数据是否过期、认证状态和强制下线原因。

## 成员

- 作为成员，我希望只在本软件中完成 Codex 官方 OAuth 登录，不复制、不上传登录 token。
- 作为成员，我希望从本软件启动受管 Codex，使额度采集、策略执行和会话状态使用同一个隔离的 `CODEX_HOME`。
- 作为成员，我希望看到自己的精确服务端额度以及房间中其他成员共享的额度快照。
- 作为成员，我希望本机只执行经过房主公钥验证的策略，拒绝被篡改或来自其他房间的策略。

## 强制下线

- 当新鲜的服务端额度快照达到或超过本人的规则阈值时，守护进程必须调用 Codex 官方 `account/logout`。
- 下线后，本软件必须把本地状态锁定到触发窗口的 `resetsAt`，并停止从软件启动 Codex。
- 锁定状态必须共享给房主；过期快照、无效签名或已经重置的窗口不得误触发下线。
- 只有成员明确启用本机强制执行后，房主策略才可以在该电脑上触发登出。

## 安全边界

- 共享目录中不得出现 Codex access token、refresh token、账号密码或完整 `auth.json`。
- 共享快照和成员资料由成员密钥签名；策略由房主密钥签名。
- 本地管理员仍可以关闭或篡改普通桌面程序；不可绕过的企业级管控需要受管设备策略，这是产品边界而不是伪装成已解决的问题。
