# Codex Quota Guard 用户旅程

## 管理员

1. 在 Web 后台创建系统用户和团队，为团队设置滚动 5 小时、7 天 Token 上限；必要时给单个用户设置覆盖值。
2. 在每位用户自己的电脑上，通过官方 ChatGPT 桌面应用或 Codex CLI 完成官方登录。后台不再接收官方凭证。
3. 在 Windows 用户电脑上以该 Windows 用户身份安装 Rust 统计程序；用户首次登录 Quota Guard 系统账户后完成设备配对。
4. 在“用户管理 → 查看额度”中查看客户端最近一次上报的官方额度百分比、该系统用户的个人 Token 用量和设备最后心跳。
5. 如有必要，禁用或强制下线**本系统账户**，或撤销计费设备令牌。系统会话操作不会退出官方应用。

## 系统用户

1. 使用本系统账户登录 Quota Guard 桌面客户端；已安装的 Rust 统计程序将与该系统用户配对。
2. 在官方应用/CLI 中自行登录 Codex；Quota Guard 不提供“登录 Codex”按钮、凭证导入或下发。
3. 查看本机读取的官方账户额度（若官方返回相应窗口），以及中央 Java 服务计算的个人 Token 上限、已用和剩余。
4. 个人额度用尽时看到提醒，联系管理员调整；官方客户端不会因此被自动关闭。

## 统计边界

本机统计程序只读取当前操作系统用户可访问的官方 Codex 会话日志，按事件 ID 幂等上报。首次启用建立基线，不追溯先前历史。Windows Rust 统计程序配对后独立于桌面窗口运行，关闭 Quota Guard 不会停止它；但程序未安装/未配对、使用另一台设备、修改日志或官方客户端未写出可读记录，仍可能造成遗漏。因此这里是本机上报统计，不是官方账单或防绕过的硬限制。普通 ChatGPT 桌面聊天不保证被计入。
